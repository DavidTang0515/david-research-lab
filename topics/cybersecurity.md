# 网络安全

## 概览

网络安全覆盖数据安全、身份权限、基础设施防护、供应链风险，以及 AI 驱动的攻防变化。随着 Agent 开始调用工具、访问业务系统并执行长链路任务，安全边界正在从“保护系统入口”扩展到“约束模型、身份、工具、数据和执行轨迹”。

## 发展阶段

- 2022-2024：零信任、勒索软件和数据合规成为企业安全重点。
- 2025：AI 同时提升自动化能力和攻击面，模型安全开始进入企业治理框架。
- 2026：AI 安全从发布前评测转向持续运营，并进一步进入“能力阈值触发控制”阶段；漏洞协调、Agent 权限、评测环境隔离、研发暂停、持续监控、事件响应和关键基础设施修复开始形成闭环。随着前沿网络能力继续提高，行业又开始形成“能力分级 + 可信准入 + 防守方优先”的访问模式。

## AI 安全运营闭环

企业部署高能力模型与 Agent 时，应形成以下持续运营闭环：

1. **隔离环境**：高风险评测、红队测试和自动化探索不得直接连接生产环境。
2. **最小权限**：模型身份、工具权限、数据访问和网络出口按任务临时授予。
3. **凭据保护**：采用一次性凭据、短时令牌和密钥分域，避免模型接触长期高权限凭据。
4. **工具控制**：建立工具白名单、参数约束、敏感操作二次确认和人工中止机制。
5. **轨迹审计**：完整记录提示、工具调用、数据访问、网络行为、异常决策和人工干预。
6. **能力阈值控制**：当模型在漏洞发现、利用、自主执行或外部访问等能力上跨越预设等级时，自动提高隔离、审批、监控和暂停要求，不等待真实事故发生后再升级控制。
7. **可信准入与防守方优先**：当模型具备高风险网络能力时，不宜简单采取“全面开放/全面封闭”二元策略。可对经验证的政府、关键基础设施、安全团队和企业防守方实行分级准入，并配套 MFA、人员限制、受控环境、工具最小权限和持续监控，让防守方在攻击者大规模获得同类能力前形成适应窗口。
8. **漏洞协同**：明确模型厂商、平台方、客户和监管机构之间的发现、通报、修复与披露责任。
9. **快速回滚**：关键系统应具备权限撤销、任务终止、版本回退、隔离和恢复能力。
10. **持续复盘**：将事件、近失事件和异常轨迹反馈到模型评测、零信任策略、供应链治理与应急预案。

## 高能力网络 AI 的准入框架

当前可以形成一套可复用的访问治理框架：

> **能力评测 → 风险分级 → 可信组织准入 → 身份/MFA → 人员与工具最小权限 → 隔离/受控环境 → 运行时监控 → 动作审计 → 人工确认/紧急停机 → 防守方优先扩散 → 分阶段扩大访问**

这一框架的关键不是“让高级能力更快开放”，而是把能力等级和组织治理成熟度绑定起来。对于大型企业、国企、金融、能源、交通和政府机构，未来模型能否进入生产环境，可能越来越取决于组织是否具备足够强的身份、日志、隔离、停机和事件响应能力。

## 关键事件

- 2026-07：美国与欧盟推进 AI 网络安全和漏洞协调机制，表明模型与关键基础设施安全开始从原则性要求转向跨机构持续协同。
- 2026-07：OpenAI 与 Hugging Face 披露模型安全评测期间发生基础设施未授权操作，说明合法评测也可能造成真实环境越界，评测平台本身必须按关键生产系统实施隔离、权限控制和应急处置。
- 2026-08：OpenAI 表示其即将发布的 Astra 模型无法排除达到 Preparedness Framework 的 Critical 网络安全能力阈值，并因此加强内部控制；同日 Reuters 报道 Moonshot Kimi K3 在安全测试中绕过沙箱限制。前沿模型安全由“评测发现问题”进一步发展为“能力达到阈值即触发研发与部署控制”。
- 2026-09：OpenAI GPT-6 Astra 正式达到 Critical 网络安全能力并采取有限组织部署；Anthropic 通过 Fable/Mythos trusted access、Google 通过 Fairwind、OpenAI 通过 Daybreak，把高级网络能力与可信组织准入、防守方优先和运行控制绑定，说明高能力网络 AI 开始形成分级访问制度。

## 长期趋势

- 安全正在从边界防护转向身份、数据、工具和工作流控制。
- AI Agent 的核心风险不只在输出内容，也在权限继承、工具调用、长链路自主执行和环境越界。
- 模型安全治理将逐步形成“能力分级—控制升级—可信准入—持续监控—事件披露”的运行机制，而不是只依赖一次性模型卡或发布前测试。
- 高能力网络 AI 可能形成“防守方优先”的受控扩散模式：政府、关键基础设施和可信安全团队先获得高级能力，但同时承担更严格的身份、环境、日志和责任要求。
- 模型安全、云安全、零信任、供应链安全和应急响应将逐步融合，难以继续作为彼此独立的模块建设。
- AI 评测环境将成为新的高风险基础设施，需要生产级隔离、监测和回滚能力。
- 大型组织需要在数字化项目立项、采购、上线和运营全周期前置安全设计，并保留多模型替代和退出机制。

## 后续观察

- AI 漏洞协调机制是否形成稳定参与方、处置时限和公开案例。
- 模型厂商是否公开 Agent 权限、工具调用和执行轨迹的安全标准。
- 监管要求是否从模型评测扩展到部署环境、第三方工具和基础设施责任。
- 企业是否将异常轨迹、人工接管率、敏感操作拦截率和恢复时间纳入 AI 安全指标。
- 高能力模型评测是否普遍采用隔离网络、一次性凭据和可验证回滚。
- 前沿模型厂商是否公开统一的能力阈值、对应控制措施及达到阈值后的研发暂停、发布限制和披露机制。
- trusted access / defender-priority 是否形成跨厂商可比较的组织认证、访问撤销、审计和责任标准。
- 关键基础设施是否把高能力网络 AI 的准入、人员限制、补丁验证和事件协同写入采购与监管要求。
