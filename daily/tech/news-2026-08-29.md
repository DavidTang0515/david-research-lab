### 2. Salesforce 与 Anthropic 扩展 Claudeforce，企业 Agent 从“应用入口”走向“受治理的能力调用层”

- 领域：企业 AI / Agent / CRM / 数据治理 / 权限治理
- 重要性：高
- 事实概述：Salesforce 与 Anthropic 宣布扩大战略合作 Claudeforce，把 Claude 的推理能力与 Salesforce 中的数据、工作流、业务逻辑、动作和治理机制连接起来，使用户可从 Claude 入口调用受 Salesforce 权限和治理约束的企业能力。Salesforce 同期还在推进 Headless 360，把应用中的业务能力通过开放标准暴露给经过授权的 Agent。

- 长期知识：企业 Agent 架构可进一步抽象为 `模型/入口层 → Agent 编排层 → 企业能力层 → 身份权限与治理层 → 核心业务系统`。模型可以替换，但业务能力、权限、审计和数据边界应保持稳定。

## 4. 对普通人的影响

**AI 会越来越多地嵌入原有办公系统，而不是要求用户不断更换应用。** Claudeforce 这类模式意味着未来可能从 Claude、Copilot 或其他入口直接调用 CRM、审批、知识库和业务流程，真正重要的是背后的权限和数据边界是否一致。

**开源和定制 AI 芯片竞争有利于长期降低单一供应商依赖，但短期不一定直接降低 AI 使用价格。** 芯片从设计到量产和收入兑现往往跨越数年，基础设施投资仍会通过订阅、调用限额和服务分层传导给用户。

**AI 的公共部门使用会越来越受到法律和政策约束。** 模型是否能用于监控、国防和自动化决策，不只是技术问题，也会影响厂商能否参与政府项目和服务连续性。

**东南亚 AI 投资从数据中心走向应用与研发，可能带来更多区域性就业和创业机会。** 真正有价值的岗位会更多集中在 AI 产品、行业实施、数据、芯片研发和系统集成，而不仅是机房建设。

## 5. 对企业和国企数字化的启示

1. **把“模型入口”和“企业能力”解耦。** OA、ERP、CRM、知识库和审批流程应通过标准 API / MCP / 服务层暴露受控能力，避免业务逻辑绑定某一个 AI 产品界面。
2. **权限与审计必须跟随业务能力，而不是跟随模型。** 无论 Agent 从哪个入口调用，原系统身份、数据权限、审批规则和审计日志都应保持一致。
3. **AI 采购增加供应资格和政策连续性评估。** 对公共部门、国企和关键基础设施尤其应评估厂商使用政策、地区可用性、监管变化、替代模型和退出迁移方案。
4. **算力和芯片项目按“收入/能力兑现时间”评估。** 不应因为厂商签订大额长期合同就假设短期供给或价格立即改善，要看验证、量产、交付和利用率。
5. **区域数字化合作不要只采购算力。** 可把人才培养、联合实验室、本地应用孵化、数据治理和行业场景作为合作条件，提高基础设施投资转化为本地生产率的概率。
6. **国产化与多供应商策略应关注接口稳定性。** 模型、芯片和云可以变化，企业的数据结构、业务规则、权限模型和审计标准应尽量保持可迁移。

## 6. 投资观察

AI 基础设施仍处于高景气，但市场开始更严格地区分**订单、收入、利润和现金流**。Marvell 的数据中心增长很强，同时 Google 合作的主要增量要到更后期体现，正说明“长期需求可见性高”与“短期业绩兑现”并不是同一件事。

企业软件的竞争重点正在从谁拥有最强模型，转向谁能把模型安全地接入业务数据、流程、权限和动作。模型入口可能快速变化，而企业能力层、治理层和数据层的价值更持久。

宏观上，高利率或重新加息的风险会提高数据中心、芯片产能和长期 AI 合同的融资成本。AI 产业景气强并不意味着科技资产估值只能单向上升。

**仅作为趋势观察，不构成投资建议。**
